## First working vertical slice (§XXI's explicit minimum bar)

Per §XXI, the first vertical slice must, using **real Claude session data** (not synthetic):

1. ingest real Claude session raw data;
2. preserve the raw events;
3. reconstruct sessions;
4. identify human and AI contribution events;
5. estimate human activity time using a range and confidence model;
6. calculate actual or allocated AI spend;
7. create an initial traditional build cost comparison;
8. generate differentiated human-versus-AI contribution narratives;
9. link contributions into a lineage graph;
10. automatically process newly observed sessions;
11. expose a session-level Contribution Intelligence report;
12. expose a project-level rollup.

This slice cuts across Phases 1, 2, 3, 4, 5 (partial), and 6 (partial) rather than being a separate phase — treat it as the acceptance bar for "Phases 1–5 done" rather than phase 9. Don't call any of Phases 1–5 `done` until the corresponding numbered item above is demonstrably true against real session data.

## Rules that apply across every phase (do not repeat inline, just obey them)

- This is not a time-tracking product, an AI usage dashboard, a token consumption dashboard, or a human-vs-AI productivity calculator — if a phase's output reduces to one of those, it has drifted from the spec.
- Never collapse the raw source event into the classified Contribution Event — the raw event is immutable evidence; the Contribution Event is a versioned, reprocessable interpretation of it.
- Never classify a shared-class contribution (reasoning, synthesis, design, architecture, etc.) as an undifferentiated 50/50 hybrid — reconstruct the individual sub-contributions per §II/§III.
- Never say "AI saved X hours" or state inferred time/cost as an observed fact — every report must distinguish OBSERVED / INFERRED / ESTIMATED / ALLOCATED / CALCULATED (§VII) and use "estimated equivalent traditional effort" language (§X).
- Never silently rewrite historical attribution — create a new attribution version and preserve prior ones (§XX).
- Do not flatter the user or auto-label their inputs as strategic/innovative — every classification must be defensible from observed behavior (§IV).
- Do not require centralizing all raw source content to make the multi-human/multi-agent channel model work — governed semantic projection is explicitly allowed (§XIV).
- Claude is the first source adapter, not a permanent architectural assumption — interfaces (§XIX) must not be Claude-specific in signature.
- A phase is not "done" permanently — re-run it whenever the source data formats, org model, or Betsy's direction has moved since the last pass.
