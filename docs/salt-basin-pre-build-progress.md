## Changelog

- **2026-07-12** — Phase 4 continuation added a Member Financial panel and connection revocation, then corrected an initial configuration-enforcement failure before handoff. Member navigation is now config-driven through `defaultMemberConfig.navigation.memberTabs`; financial provider enumeration, ordering, availability, labels, experience defaults/copy, account classes, liability classification, scopes, and derived share types resolve through `financialPolicyRegistry.js`. Existing member config rows are not mutated by bootstrap; the draft-config response additively supplies the default navigation when an older row has no navigation key.

- **2026-07-12** — Advanced Phase 4 (Financial Connections & Personal Financial Channels). Added `financial_consents`, `external_financial_connections`, `financial_account_definitions`, and `financial_output_shares`; raw connection/account rows are structurally `MEMBER_PRIVATE` and intentionally have no Organization scope. Added `financialPolicyRegistry.js` for provider classes, account/liability classification, security/retention IDs, canonical Data Scope, and permitted derived share outputs. Added `/api/member-financial` routes for Member-owned connection/account creation and explicit Organization-output share/revoke/read flows. Credentials/tokens are not accepted by these routes and do not become Evidence Atoms. Unit policy tests pass (4/4); production Vite build completed. Phase remains in progress because real Plaid Link/token-vault integration, source refresh, semantic Atom population, and interacting-user UI verification are not built yet.
