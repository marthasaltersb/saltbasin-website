## Items

### RI-R1-1 [defect] Importer exits 1 on the repo's own generated logs (E.1)
- Root cause: `importRepository` (`server/lib/releaseLogImporter.js` ~355-375) walks every `.md` under `docs/release-log/`; `classifyPath` (`server/lib/releaseLogParser.js:112`) treats ALL of them as `release_log`. `docs/release-log/release-tracker.md` and `updates.md` are tracker-generated files, not release logs; they have no `Date:` so line 150 of the importer throws (correctly, per E.3), counted in `errors`, and `scripts/import-release-logs.mjs` exits 1.
- Reproduced by code path (both files named in the run output "Read 66 file(s); 2 error(s)"); behaviour matches the change spec ("exit non-zero on any error"), so the step is right and the product is wrong to feed it non-logs.
- Fix: add a configurable `generatedFiles` (or `ignoredFiles`) list to `releaseIntelligenceConfig.js` defaults (`release-tracker.md`, `updates.md`), validated and editable on the Settings tab. `importRepository` skips them with an explicit `skipped` line ("generated by release-tracker-sync, not a release log"), not silently. Leave the E.3 refusal for pasted/real release logs untouched. Re-run twice: expect exit 0.

### RI-R1-4 [defect] Wide tables are not scrollable inside the card
Steps: J3.1, E.3, J10.1, J10.2, J10.5 (Releases list); J3.2-J3.4 etc. (Features table 573-641px); J4.1-J4.6, J5.2, J7.5, J7.8, E.5 (runs table 493-604px); J6.2, J6.3 (Outputs 808px); J10.3 (history).
- Root cause: `S.table` (line 24) is `width:100%` with no wrapper, and tables at lines 103, 183, 277, 332, 349, 477 contain many columns, so the table's min-content width exceeds the card, bleeding out of it.
- Fix: wrap each table in a shared `<div style={{overflowX:'auto', maxWidth:'100%'}}>` (a small `TableScroll` component), keep the card at `minWidth:0`. Scrolling inside the table is acceptable: the clipping rule is about content escaping the card; the validator must scroll within the wrapper. (If the owner wants no horizontal scroll at all, stack rows as cards under 600px; raise that as an observation, not a blocker.)

### RI-R1-5 [defect] Auto-fit grids with large minmax force 420/320/280px columns
Steps: J8.2-J8.6, J9.6 (Trends charts 420-462px wide), J3.2/J3.3 (check-line grid).
- Root cause: line 178 `repeat(auto-fit, minmax(420px, 1fr))`, line 301 `minmax(280px,1fr)`, line 579 `minmax(320px,1fr)`. Under ~460px of available width the column cannot shrink below the minmax, so the charts (their SVG is `width:100%` and fine) overflow.
- Fix: use `minmax(min(100%, 420px), 1fr)` (same for 280/320). `releaseCharts.js` needs no change.

### RI-R1-6 [defect] Card appears shifted left (-23..-71px)
Steps: J4.5, J4.6, J6.3, J8.2 and E.3 (card left edge negative, heading cut).
- Root cause: derived from RI-R1-3/4/5. `embedBody` in `WorldShell.jsx:1409` is `overflowY:auto` which makes overflow-x auto too; when children overflow, focusing/clicking an off-card input scrolls the container horizontally, so the card's left edge reads negative. Not a separate layout rule.
- Fix: resolve RI-R1-3/4/5; additionally set `overflowX:'hidden'` on the Release Intelligence root (`S.root`, line 17: add `minWidth:0, boxSizing:'border-box', overflowX:'hidden'`) as a guard. Re-validation at 390px should confirm left edge >= 0 on every tab.
