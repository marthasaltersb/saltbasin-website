### platform-mcp-r4-T1 - J10.4 (and the exit code of J11.2) - class: defect - MCP_GAP release-tracker-admin
Root cause: the live release tracker's administration routes (`POST /api/release-tracker/snapshots`, `/pull`, `GET|PUT /settings`, `POST /settings/webhook-secret`, `GET|POST /tokens`, `DELETE /tokens/:id`, `GET /snapshots`, `GET /ingest-log`, server/routes/releaseTracker.js lines 76-175) have no MCP tools. `server/lib/mcpToolRegistry.js` registers only `release_tracker_get_state` (line ~874). The other descriptors exist in `RELEASE_TRACKER_TOOLS` (server/lib/releaseTrackerService.js lines 505-514, comment "not registered yet") but the registry never imports them. `server/lib/capabilityParity.js` line 174 therefore has `mcp: null` plus a `gap:` string, so the Capabilities card "Ingest, pull, settings, tokens and logs (admin)" shows an MCP gap, Gaps only shows 1 card (J10.4) and `check-interface-parity.mjs --strict` exits 1 (J11.2). Introduced by da35a40 (release scope fix r1), which registered only get_state. It is the unfinished part of platform-mcp-B5 and breaks the interface-parity rule (every capability works as website, API and MCP tool with the same permissions).
Fix:
1. server/lib/mcpToolRegistry.js: register one tool per route, each calling the same service function the route calls, `permission: 'admin'` (routes use requireAdmin; the ingest-token path is a CI bearer path and stays out of MCP because an MCP caller is a signed-in user). Suggested: `release_tracker_list_snapshots` (`listSnapshots(limit)`), `release_tracker_list_ingest_log` (`listIngestLog`), `release_tracker_get_settings` (`loadSettings` plus `streamClientCount()` as the route does), `release_tracker_list_tokens` (`listTokens`) under scope release.read; `release_tracker_ingest_snapshot` (parse string snapshot/history/updates as the route does, source 'manual'), `release_tracker_pull_now` (`pullFromRepo({source:'pull'})`), `release_tracker_save_settings`, `release_tracker_webhook_secret` (generate or `clear: true`), `release_tracker_create_token` (for kind `share` call `assertReadyToFinalize(user.id)` first, exactly as the route, so a public share link cannot be minted around the finalization gate), `release_tracker_revoke_token` under scope release.write. Keep `status`/`code` on errors (TrackerError carries them).
2. server/data/mcpToolManifest.json: append the new names (append-only).
3. server/lib/capabilityParity.js line 174: set `mcp: [...new names]`, delete `gap`. Keep it ONE row so the total stays 121 and the summary reads 121 of 121 (splitting the row changes the number the J11.2 amendment must pin).
4. Remove the "not registered yet" comment in releaseTrackerService.js and the matching "known limitation" text in docs/changes/live-release-tracker.md and docs/changes/platform-mcp.md; list the new tools and scopes there.
Verification: `node scripts/check-interface-parity.mjs --strict` exits 0 printing `Interface parity: 121 of 121 ... (website UI gaps: 0, MCP gaps: 0, API gaps: 0)` with no Gaps line; Capabilities > Gaps only shows the no-gaps message at 1280 and 390 px.
Files: server/lib/mcpToolRegistry.js, server/lib/capabilityParity.js, server/lib/releaseTrackerService.js, server/data/mcpToolManifest.json, docs/changes/platform-mcp.md.
